# Lolka × OpenClaw Bridge

**Двусторонний мост между [Lolka](https://lolka.app) и сессиями агентов [OpenClaw](https://docs.openclaw.ai).**

Каждый канал Lolka привязывается к конкретной сессии агента: сообщения из канала попадают в сессию, ответы агента возвращаются в канал. Из чата доступны команды управления сессией — смена модели, компакция контекста, статус, рестарт гейтвея.

Lolka — российский аналог Discord с Bot API, совместимым с Discord API v10. Поэтому мост устроен так же, как типовой Discord-мост: `lolka.js` — форк `discord.js`, REST и Gateway повторяют Discord, а перенос существующего Discord-бота сводится к замене импорта. Отличия и подводные камни платформы собраны в разделе [«Ограничения Lolka Bot API»](#ограничения-lolka-bot-api).

## Зачем это нужно

Агенты OpenClaw живут в своих сессиях — в веб-интерфейсе, в терминале, в API. Но общаться с ними удобнее там, где уже идёт рабочая переписка. Мост превращает канал Lolka в полноценный пульт:

- **одна сессия — один канал**: контекст не смешивается, история остаётся в канале;
- **видно, что делает агент**: уведомления о вызовах инструментов, статус сессии, расход токенов;
- **управление на ходу**: сменить модель, сжать контекст, остановить прогон, перезапустить гейтвей;
- **реплики владельца от его имени**: через вебхук канала, с именем и аватаром, а не «от бота».

## Возможности

### Обмен сообщениями

| Возможность | Детали |
|---|---|
| Канал → сессия | `messageCreate` → `sessions.send` с ключом сессии и `agentId`; текст помечается префиксом `[Lolka/<канал>]` |
| Сессия → канал | подписка на `session.message`; финальные ответы публикуются от бота |
| Реплики владельца | публикуются через входящий вебхук канала с именем и аватаром автора (вебхук создаётся автоматически) |
| Анти-эхо | дедупликация по `idempotencyKey` и по тексту входящего сообщения (окно 30 с) |
| Фильтр служебного | пропускаются промежуточные реплики `stopReason=toolUse`, heartbeat-прогоны, runtime-события, сообщения об ошибке прогона |
| Нарезка длинных ответов | сообщения режутся на части (~1900 символов) с сохранением порядка |

### Надёжность доставки

`outbox.js` — очередь отправки, один воркер на канал:

- строгий порядок сообщений в канале, без гонок между параллельными ответами;
- ретраи `5 / 10 / 15 / 20 / 25 с` (настраивается);
- «парковка» при длительном сбое: буфер удерживается до следующего сообщения или страховочного таймера, затем отправляется;
- постоянные 4xx (кроме `429`/`408`) уходят в `outbox-dead.jsonl` (dead-letter), чтобы не блокировать очередь;
- состояние (`outbox.json`) восстанавливается при старте — непереданное не теряется;
- `kind=edit` — правка уже отправленного сообщения (используется тикером инструментов).

### Управление сессией

`/status` приходит с кнопками **Обновить / Компакция / Стоп** (компоненты Lolka, Discord-совместимые, `custom_id = bridge:*`). Клик обрабатывается как интеракция и обновляет то же сообщение.

### Контекст

- оценка заполнения окна по `contextBudgetStatus` из `sessions.describe`;
- плашка при достижении порогов (по умолчанию `80 / 95 / 100 %`);
- принудительная компакция, если сессия «залипла» на полном контексте (автокомпакция OpenClaw иногда не срабатывает);
- детектор «чат молчит»: сообщение без ответа дольше порога при полном контексте → плашка + компакция.

### Уведомления о работе агента

- **вызовы инструментов**: `⚙ Exec`, `✎ Edit`, `🔍 Read`, `🌐 Web`, `🔧 прочее`;
- **стили**: `code` (по умолчанию), `quote`, `spoiler`, `plain`, `off`;
- **тикер**: серия вызовов оформляется одним сообщением, которое дописывается через `PATCH` (окно 15 строк, старые сворачиваются в «… ещё N раньше»);
- **ссылки вырезаются** из уведомлений (иначе мессенджер подтягивает превью и ломает вид).

### Мультибот и мультиагент

Один и тот же `bridge.js` обслуживает несколько ботов Lolka и несколько агентов OpenClaw одновременно — см. [раздел ниже](#мультибот-несколько-ботов-и-агентов).

## Как это работает

```text
        Lolka (сервер)                                    bridge.js                                   OpenClaw Gateway
 ┌───────────────────────┐                        ┌───────────────────────────┐                    ┌─────────────────────┐
 │ сообщение в канале    │ ──── messageCreate ──► │ фильтры → команда/агент   │                    │                     │
 │ (текст, автор, id)    │                        │                           │ ── sessions.send ─►│ сессия агента       │
 └───────────────────────┘                        │  WS-клиент (operator)     │                    │ (модель, контекст,  │
                                                  │  подписки на события      │◄─ session.message ─│  инструменты)       │
 ┌───────────────────────┐                        │                           │◄─ session.operation│                     │
 │ канал: ответы бота    │ ◄── REST / webhook ─── │  outbox (очередь)         │◄─ agent (tool)     │                     │
 │ канал: реплики людей  │                        │  typing / тикер / плашки  │                    │                     │
 └───────────────────────┘                        └───────────────────────────┘                    └─────────────────────┘
```

**Поток 1 — сообщение из Lolka.** `messageCreate` → проверка маппинга и фильтры → если строка начинается с `/`, это команда (только владелец), иначе `sessions.send` в привязанную сессию.

**Поток 2 — ответ агента.** Событие `session.message` с ролью `assistant`. Промежуточные реплики (`stopReason=toolUse`) пропускаются, финальная проходит через `sendFinal` → `botSend` → `outbox` → `POST /channels/{id}/messages`.

**Поток 3 — работа инструментов.** Событие `agent` с `data.kind="tool"` → строка в тикер → правка сообщения через `PATCH`.

**Поток 4 — команды.** `/…` → проверка владельца → RPC к гейтвею (`sessions.patch`, `sessions.describe`, `sessions.compact`, `sessions.abort`, `sessions.create`, `models.list` и др.) → ответ в канал.

**Поток 5 — контекст.** При событиях сессии мост периодически читает `sessions.describe`, считает заполнение окна и при необходимости показывает плашку и запускает `sessions.compact`.

### Что использует мост

| Сторона | Методы |
|---|---|
| OpenClaw Gateway (WS-RPC) | `sessions.send`, `sessions.list`, `sessions.describe`, `sessions.patch`, `sessions.compact`, `sessions.abort`, `sessions.create`, `sessions.messages.subscribe`, `sessions.subscribe`, `models.list` |
| Lolka Bot API (REST) | `GET/POST /channels/{id}/messages`, `PATCH /channels/{id}/messages/{id}`, `GET /channels/{id}/messages?limit=`, `GET/POST /channels/{id}/webhooks`, `POST /guilds/{id}/channels`, `POST /channels/{id}/typing` |
| Lolka Gateway (WebSocket) | `messageCreate`, `interactionCreate` (кнопки), `ready` |

## Мультибот: несколько ботов и агентов

Один процесс обслуживает несколько независимых ботов Lolka. Набор файлов выбирается суффиксом:

```bash
LOLKA_CFG_SUFFIX=-bot2 node bridge.js
```

| Файл | Без суффикса | С суффиксом `-bot2` |
|---|---|---|
| Конфиг маппингов | `bridges.json` | `bridges-bot2.json` |
| Токен бота | `.token` | `.token-bot2` |
| Владелец (кэш) | `.owner.json` | `.owner-bot2.json` |
| Очередь | `outbox.json` | `outbox-bot2.json` |
| Лог | `bridge.log` | `bridge-bot2.log` |

Каждый экземпляр — отдельный процесс со своим WebSocket к Lolka, своим подключением к гейтвею и своей очередью. Экземпляры не пересекаются: подписки идут только на свои `sessionKey`.

Типовой сценарий — второй бот на другом сервере для другого агента:

```ini
# ~/.config/systemd/user/lolka-bridge-bot2.service
[Service]
Environment=LOLKA_CFG_SUFFIX=-bot2
ExecStart=/usr/bin/node %h/lolka-openclaw-bridge/bridge.js
```

Агенты задаются в маппинге: `agentId` в `bridges.json` указывает, к какому агенту OpenClaw относится канал. В одном экземпляре можно держать каналы разных агентов — достаточно разных `sessionKey` + `agentId`.

## Требования

| Что | Версия / примечание |
|---|---|
| Node.js | 22+ |
| OpenClaw | Gateway на `ws://127.0.0.1:18789`; scopes `operator.read` + `operator.write` + `operator.admin` (admin нужен для `sessions.patch`) |
| Бот Lolka | приложение в [портале разработчика](https://lolka.app/developers/portal), бот приглашён на сервер |
| Права бота | `VIEW_CHANNEL`, `SEND_MESSAGES`, `MANAGE_WEBHOOKS`, `MANAGE_MESSAGES` (правка сообщений) |

## Быстрый старт

```bash
# 1. Код
git clone https://github.com/<owner>/lolka-openclaw-bridge.git
cd lolka-openclaw-bridge
npm install

# 2. Конфиг
cp bridges.example.json bridges.json
cp .token.example .token      # токен бота Lolka (портал разработчика)
$EDITOR bridges.json          # guildId, channelId, sessionKey, agentId

# 3. Проверка токена и серверов
npm run smoke

# 4. Запуск
node bridge.js
```

Дальше — [systemd-юнит](#деплой-через-systemd), чтобы мост жил постоянно.

## Конфигурация

### `bridges.json`

```json
{
  "guildId": "000000000000000000",
  "mappings": [
    {
      "channelId": "000000000000000001",
      "name": "general",
      "sessionKey": "agent:main:main",
      "agentId": "main",
      "webhookUrl": "",
      "notices": true
    }
  ]
}
```

| Поле | Обязательное | Смысл |
|---|---|---|
| `guildId` | да | id сервера Lolka (используется `/chatadd` при создании канала) |
| `channelId` | да | id канала Lolka |
| `name` | да | человекочитаемое имя канала (в логах и уведомлениях) |
| `sessionKey` | да | ключ сессии OpenClaw, например `agent:main:main` |
| `agentId` | нет | агент OpenClaw; нужен для `sessions.patch` и подписок |
| `webhookUrl` | автозаполнение | URL входящего вебхука канала; создаётся при первом старте |
| `notices` | нет | уведомления о вызовах инструментов в этом канале |
| `ctxWarn` | нет | плашка о заполнении контекста (по умолчанию включена) |
| `ctxCompact` | нет | принудительная компакция (по умолчанию включена) |
| `toolStyle` | нет | `code` / `quote` / `spoiler` / `plain` / `off` |
| `toolTicker` | нет | серия вызовов одним сообщением (по умолчанию включено) |
| `typing` | нет | индикатор набора (см. ограничения платформы) |

Флаги, изменённые командами из чата (`/notices`, `/toolstyle`, `/toolticker`, `/typing`, `/ctxwarn`, `/ctxcompact`), сохраняются в файл и применяются сразу.

### Токены и секреты

| Секрет | Источник | В репозитории |
|---|---|---|
| Токен бота Lolka | `LOLKA_BOT_TOKEN` или файл `.token` (`.token-<суффикс>`) | нет — `.gitignore` |
| Токен гейтвея OpenClaw | `~/.openclaw/openclaw.json` → `gateway.auth.token` (путь через `OPENCLAW_CONFIG_PATH`) | нет — файл вне репозитория |
| URL вебхука канала | создаётся через API, пишется в `bridges.json` | нет — публикуется только пример с пустым полем |
| id владельца | `.owner.json` | нет |

## Команды в чате

| Команда | Действие |

| `/ctxcompact on\|off` | принудительная компакция при полном контексте |
| `/compact` | сжать контекст сейчас |
| `/stop` | прервать текущий прогон |
| `/notices on\|off` | уведомления о вызовах инструментов в канале |
| `/toolstyle code\|quote\|spoiler\|plain\|off` | оформление уведомлений |
| `/toolticker on\|off` | серия вызовов одним сообщением |
| `/typing on\|off` | индикатор набора в канале |

| `/help` | список команд |

Команды выполняет **только владелец** (подробнее — [«Безопасность»](#безопасность)).

## Деплой через systemd

```ini
# ~/.config/systemd/user/lolka-bridge.service
[Unit]
Description=Lolka <-> OpenClaw text bridge
After=network-online.target

[Service]
Type=simple
WorkingDirectory=%h/lolka-openclaw-bridge
ExecStart=/usr/bin/node %h/lolka-openclaw-bridge/bridge.js
Restart=always
RestartSec=5

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now lolka-bridge.service
loginctl enable-linger "$USER"     # мост живёт без активной сессии
journalctl --user -u lolka-bridge -f
```

## Ограничения Lolka Bot API

Проверено на живом API (октябрь 2026):

- **Индикатор набора от ботов не транслируется.** `POST /channels/{id}/typing` отвечает `204 No Content`, но это заглушка-no-op: «запрос принимается, но индикатор не транслируется; эндпоинт оставлен для совместимости с Discord-клиентами» ([документация](https://lolka.app/developers/bots/channels)). Мост всё равно держит вызов — если платформа включит трансляцию, индикатор заработает без правок.
- **Правка сообщений**: `PATCH` работает, `PUT` — `404`.
- **`TYPING_START`** — только входящее событие: бот его получает, но отправить не может.
- **Лимиты частоты**: при превышении `429`; нужен backoff (в outbox он есть).
- **Права**: без `VIEW_CHANNEL` / `SEND_MESSAGES` большинство запросов вернёт `403`.
- **Снежинки**: 64-битные id, в JSON всегда строки — сравнивать как строки, не парсить в `Number`.

## Безопасность

- **Команды — только владельцу.** Владелец определяется по id из `.owner.json`. Права `Administrator`/`ManageGuild` намеренно не учитываются: команды дают доступ к сессиям, смене модели и рестарту гейтвея. Расширить круг можно явно — `LOLKA_ADMINS=id1,id2`.
- Остальные участники получают ответ «команды моста доступны только владельцу сервера» (не чаще раза в минуту на канал).
- Обычный текст уходит агенту от любого участника канала. Если это не нужно — добавьте проверку на входе (точка расширения — обработчик `messageCreate`).
- Токен бота даёт полный доступ к боту: только `.token`/env, никогда в репозиторий и логи.
- URL вебхука содержит секрет — `bridges.json` в `.gitignore`.

## Диагностика

```bash
LOLKA_BRIDGE_DEBUG=1 node bridge.js           # сырые события в events.jsonl
npm run test:outbox                           # регресс очереди
```

Метки в логе: `[gw]` — соединение с гейтвеем, `[lolka]` — сторона Lolka, `[lolka->oc]` — входящее сообщение, `[lolka->cmd]` — команда, `[oc->lolka]` — публикация, `[hook]` — вебхуки, `[typing]` — индикатор, `[owner]` — определение владельца, `[outbox]` — очередь, `[ctx]` — контекст, `[oc] skip …` — что и почему отфильтровано.

Типовые проблемы:

| Симптом | Причина и решение |
|---|---|
| Мост молчит, процесс жив | нет реконнекта к гейтвею: проверьте `[gw] close/error`; мост переподключается по `close` и `error`, сторож — 30 с |
| `403` на отправку | у бота нет `SEND_MESSAGES` / `VIEW_CHANNEL` в канале |
| Сообщения дублируются | два инстанса на один канал или старый `outbox.json` — остановите лишний процесс |
| Команды не работают | пишет не владелец; проверьте `.owner.json` и `LOLKA_ADMINS` |
| `[typing] → HTTP 401` | протух токен бота — перевыпустите и обновите `.token` |

## FAQ

**Нужен ли Discord?** Нет, только Lolka. API совместим с Discord v10, поэтому знакомые библиотеки и примеры почти всегда переносятся.

**Можно ли привязать один канал к нескольким агентам?** Нет, связь 1:1. Для второго агента — второй канал (или второй бот и отдельный экземпляр моста).

**Что будет, если гейтвей перезапустится?** Мост переподключится сам; непереданные сообщения останутся в очереди.

**Работает ли это с Discord напрямую?** Схема та же, но код рассчитан на Lolka: используется `lolka.js` и `lolka.app` REST/Gateway.

**Почему «печатает» не видно?** Это ограничение платформы — см. [«Ограничения Lolka Bot API»](#ограничения-lolka-bot-api).
